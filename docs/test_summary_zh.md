# cp2graph 测试总结文档

本文档汇总 `cp2graph` 项目已执行的核心实验、结果与解释，目标是回答三个问题：

1. 功能是否正确（Correctness）
2. 性能是否达标（Performance）
3. 语义哈希是否稳定且低冲突（Hash Robustness）

---

- 操作系统：Windows

- 关键依赖：`networkx`、`lark`、`pytest`、`pytest-cov`

### 1.2 实验分类

- A 类：功能与回归测试（单元测试 + 集成测试）
- B 类：覆盖率测试（分支覆盖）
- C 类：性能基准测试（10k 行模型）
- D 类：语义哈希冲突抽样实验（10,000 随机模型）

## 3. C 类实验：性能基准（10k 行）

### 3.1 实验设计

执行命令：

```bash
python scripts/benchmark.py --max-seconds 2.0 --lines 10000
```

脚本行为：

- 自动构造约 10k 行的 FlatZinc 文本
- 执行解析 + 归一化 + 建图全流程
- 统计耗时、节点边数量、粗略内存估计
- 若耗时超 2.0 秒或估算内存超阈值则直接失败

### 3.2 实验结果

- `elapsed_seconds = 1.4965`
- `nodes = 101`
- `edges = 200`
- `text_bytes = 269997`
- `rough_graph_bytes = 77056`
- `bound = 1349985`（文本大小 x5）

### 3.3 结果解释

- 时间目标：要求 `<= 2s`，实测 `1.4965s`，满足要求。
- 内存目标：要求不超过文本体积 `x5`，粗略估计显著低于阈值。
- 图规模较小是因为规范化阶段去重了大量等价约束，这符合设计预期。

## 4. D 类实验：哈希冲突抽样（10,000）

### 4.1 实验设计

执行命令：

```bash
python scripts/hash_collision_check.py --samples 10000 --seed 42
```

脚本行为：

- 生成 10,000 个随机模型
- 各模型生成图并计算图级语义哈希（`blake2b-128`）
- 若出现“不同图同哈希”计为冲突

### 4.2 实验结果

- `samples = 10000`
- `collisions = 0`

### 4.3 结果解释

- 在 10,000 样本中未观测到冲突，符合低冲突预期。
- 该结果属于**经验抽样验证**，不是严格数学证明。

---

## 5. 关键结论

1. 正确性：20/20 测试通过，核心能力稳定可用。  
2. 覆盖率：总覆盖率 92%，满足 CI 门禁要求。  
3. 性能：10k 行模型在 1.4965 秒内完成，满足 2 秒目标。  
4. 哈希稳健性：10,000 随机样本未发现冲突。  

---

## 6. 已知边界与风险

- `parser.py` 对极端/非常规 FlatZinc 语法分支仍有扩展空间。
- 性能基准当前为单规模（10k 行），建议补充多规模曲线（1k/5k/10k/20k）。
- 哈希冲突验证当前为抽样，建议在 CI 增加周期性更大样本回归。
